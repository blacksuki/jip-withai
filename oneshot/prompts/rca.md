【最重要・様式の厳守 — 独自CSS/独自章立ての新規作成は禁止】
1) **必ず最初に** 次のスケルトンを read ツールで開くこと（省略不可）：
   `C:/Users/MingZhengHuo/workspace/29.JIP/sample/templates/report_skeleton.html`
2) 出力HTMLは、このスケルトンを**土台としてそのまま使う**。
   ・`<style>` ブロック（CSS変数・クラス定義）は **一字一句そのまま流用**。独自CSSを書き起こさない。
   ・`{{ ... }}` のプレースホルダを分析結果で置き換える形で作る。
   ・HTMLのクラス名（`meta` / `pill pill-bad` / `pre class="before"` / `pre class="after"` /
     `box box-bad` / `box box-warn` / `box box-good` / `filepath` / `flow` / `badnode` 等）は
     スケルトンのものを**そのまま使用**する。新しいクラス名を発明しない。
3) 章立ては次の見出しを**この順・この文言で**厳守（変更・追加・改名しない）：
   0. エグゼクティブサマリ（`class="meta"` の表 + `box box-bad` の結論。QA番号/件名/環境/
      リビジョン/依頼区分/事象/直接原因/根本原因/区分 `pill`/結論 を必ず記載）
   1. 直接原因（プログラム観点）— `class="filepath"` + `<pre class="before">`で実コード引用 + `box box-bad`
   2. 根本原因（設計・プロセス観点）— なぜ発生/なぜ検知漏れ/仕様誤認の表
   3. 修正案（変更前後）— `<pre class="before">`(変更前) と `<pre class="after">`(変更後) を必ずペアで
   4. 再発防止策（プログラム表 + テスト観点）
   5. 参照ソースファイル一覧（層／ファイル／該当箇所の表）
4) 区分 `pill` は事実に応じ `pill-bad`（不具合）/`pill-warn`（仕様・要確認）/`pill-good` を使い分ける。
5) `<footer>` に「自動生成（要レビュー）」を残す。

【出力後の自己チェック（満たさなければ書き直す）】
- `<pre class="before">` と `<pre class="after">` が各1つ以上あるか
- `class="meta"` の概要表と `pill` バッジがあるか
- 章見出し 0〜5 が上記文言どおり揃っているか
- スケルトンの `<style>` を流用しており独自CSSになっていないか
